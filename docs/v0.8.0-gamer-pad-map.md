### 1.2 Registration order (source-confirmed)

1. `Phase1::InstallFrameHook` installs the `GetUnusedPadID` detour once, at ASI load (`phase1.cpp` 1314). No uninstall appears in that function. The detour lives for the process.
2. On integrate, `g_blockReg = newEntity` is stored **before** `World::AddEntity` (`phase1.cpp` 336–337).
3. `SetPosition` follows (`342–343`).
4. Optional `PlayerPadManager::FromWorld` + `RegisterPlayer(newEntity, 1)` only for the non-net, `RegisterPad1` path (`345–352`). The pad index is the literal `1`, not the index the hook just chose.
5. `DespawnPuppet` clears `g_puppet` and `g_blockReg` **before** `World::RemoveEntity` (`855–870`).
6. If the puppet's vtable is gone, `OnFrame` drops `g_puppet` and `g_blockReg` together and does not call `RemoveEntity` (`1055–1058`).

`g_blockReg` is not an enroll-only flag. It stays set from before `AddEntity` until despawn or world-free (`phase1.cpp` 51, 336, 859, 1058, 1161). While it is set, **every** `GetUnusedPadID` call takes the empty-slot path, not only the enroll call.

### 1.3 Unused-slot selection (source-confirmed)

`MyGetUnusedPadID` (`phase1.cpp` 1160–1171):

- If `g_blockReg` is null, call the original.
- If it is set, scan indices `0 .. 7`.
- The first `void*` slot that is null is written to `*out` and the hook returns `1`.
- If no null slot exists, call the original.
- The scan does **not** reserve slot 0. If slot 0 is empty, the hook returns 0.
- The author comment says the original returns the active pad when the unused search fails. That fallback is **AD**. The hook itself does fall through to the original when the table looks full (**SC**).

`PlayerPadManager.h` lines 8–11 say a networked puppet must not take a pad. The hook still answers with an empty index if the engine asks. Those are different mechanisms:

| Mechanism | Networked puppet | Tag |
|-----------|------------------|-----|
| `RegisterPlayer` | Not called | **SC** |
| `GetUnusedPadID` hook | Returns an empty index while the marker is set | **SC** |
| "Must not take a pad" | Header rule | **AD** |
| Engine still creates a gamer for that empty index | Comment | **AD** |

### 1.4 Cleanup

| Event | Marker | Hook | Tag |
|-------|--------|------|-----|
| `DespawnPuppet` | Cleared before `RemoveEntity` | Left installed | **SC** |
| World freed the entity | Cleared with the dangling pointer | Left installed | **SC** |
| Second clear | The stores are plain null assignments; a second despawn returns immediately because `g_puppet` is already null (`856`) | Still installed | **SC** |

The comment on line 51 says the marker suppresses `RegisterPlayer`. The hook does not intercept `RegisterPlayer`. It intercepts `GetUnusedPadID`. The optional `RegisterPlayer(pad=1)` path can still run while the marker is set, if net is off and the ini flag is on (**SC**).

## 3. Isolation invariants

A remote puppet must satisfy all of these before any future engine enroll is even considered. The policy functions return decisions. They do not perform the enroll.

1. Never call a pad-register operation for a remote puppet. An explicit "bind slot N" request is still refused.
2. Never select or bind an occupied slot.
3. Never select or bind the slot reserved for the local player.
4. If the local player's slot is not known, refuse selection and refuse bind. Do not guess.
5. If the slot-table capacity is unknown, refuse. Do not substitute the AC4 loop bound of 8.
6. If the table is full, return no slot. Do not fall through to "the active pad".
7. Arm an isolation marker before enroll. A clear marker blocks the precondition.
8. Clear the marker before teardown. Clearing is idempotent. A marker left set fails the isolation report.
9. Remote state must not acquire local input, write local inventory, write local control, or register as a second locally controlled player.
10. An empty non-local index is acceptable only when a caller opts into `AllowEmptyNonLocal` because an engine query was proven. The default is `RefuseAll`. Resynced has not proven that query.
11. `IsolationPreconditions::Ready` means the marker, role, and bind mode are consistent. It is not permission to call the game.

## 5. Offline test plan

Implemented in `tools/gamer_pad_policy_test` (CTest name `GamerPadPolicy`):

- Unknown or zero capacity does not select a slot and does not assume 8.
- Null occupancy is rejected.
- Selection skips the reserved local slot and every occupied slot.
- Unknown local owner refuses selection.
- A full table yields no slot.
- Remote `RegisterPlayer` is refused for both bind modes.
- Local explicit bind allows only an empty, non-reserved, in-range slot.
- Marker arm/clear is idempotent, and enroll preconditions follow that state.
- Isolation report fails closed for local input, inventory, control, second-local registration, occupied/local/unknown binds, a disarmed enroll, and a sticky marker.
- Empty non-local bind passes only under `AllowEmptyNonLocal`.
- `PadBindRequirementFor(Resynced106)` stays `Unknown`.

Not implemented, because they need a proven Resynced callee:

- A real `GetUnusedPad`-equivalent xref and its object lifetime.
- Proof that world enroll does or does not touch a pad.
- Any native register/unregister call. Those stay refused.

## What “remote Edward behaves like the peer” requires

A second rendered Human has to exist first (PR #29: not proven, spawn stays refused). After that, visible behavior needs a main-thread apply of the peer's action, in this order, with one writer:

1. Share the local character action set **once** (repeating it resets the puppet toward idle).
2. On alias change only, set the target action (alias, body-part channel, layer). Seek phase only when the ratio is inside the open interval (0, 1). Setting the same action again is a known crash risk on the original mod.
3. Patch blend-in after that edge.
4. Every frame, persist then write the **full primary** blend array, then write time scale. Time scale must be finite and **> 0**.
5. Blend writes go to controller channel 0 / the primary layer. The body-part channel used to *select* the action is a different value.
6. Behavior/AI and this replication must not both write. After a behavior toggle, wait 4 frames with no external action writes.

That sequence is source-confirmed for the original x86 mod (citations below). It is a **hypothesis** for Resynced until each native step is rediscovered.

## Serialization boundary

`ActionSnapshot` is our own packet, version 1, 216 bytes, little-endian, packed:

`u32 version, u32 alias, u16 targetChannel, u16 targetLayer, f32 ratio, f32 timeScale, u16 blendCount, u8 hardCut, u8 flags, f32 blendInLength, u32 sequence, f32 blend[46]`.

| Rule | Where it is enforced |
|------|----------------------|
| Version must be 1 | `Validate` / `Decode` |
| `timeScale` finite and > 0 | Rejected, not clamped |
| Ratio, blend-in length, and used blend factors finite | Rejected |
| Blend-in length ≥ 0 | Rejected when negative |
| `blendCount` above 46 | Clamped to 46 on the wire. Factors past the ceiling are dropped. |
| No game offsets in the payload | The snapshot has no RVAs and no field displacements |

Agent 1 answered the range questions from executable paths at `68355c71` (PR #28 comment 6835360174):

| Value | Wire rule | Seek / apply rule |
|-------|-----------|-------------------|
| `actionRatio` | Finite. 0 and 1 are kept. | Seek only when the ratio is inside (0, 1). |
| Blend factors | Finite. No `[0,1]` rejection. | Count clamps to 46. Factors are copied raw. |
| Blend channel / layer | Not on the wire as the target channel. | Literals 0 and 0. Target channel and layer stay the wire fields. |

This snapshot is **not** wired into `PlayerStatePayload` / `PlayerStateExPayload`. Those messages stay the coarse pose/presence protocol.

## Apply planner (no engine)

`PlanApply` is one call per intended player tick.

| Condition | Result |
|-----------|--------|
| Thread is not main | `wrong-thread`. Cooldown does not move. |
| Snapshot invalid | Validation reason. Cooldown does not move. |
| Cooldown > 0 | Decrement, `cooldown`, no writes. |
| `HybridGround` and behavior enabled | `behavior-owns-gait`. Host must clear `behaviorEnabled` before air replication. The planner does not detect ground itself. |
| `Idle` or `BehaviorOnly` | `replication-not-writer` |
| `ReplicationOnly` while behavior is still enabled | `dual-writer` |
| Allowed | Action set once; target and blend-in fix only when `alias` changes; seek only on that edge and only when the ratio is inside (0, 1); persist + blend write + time scale every allowed frame. Blend channel/layer in the plan are the literals 0/0 even when `targetChannel` is not. |

`ApplyToFake` mutates only an in-memory double, and only when the plan is allowed. A refused plan leaves the double unchanged.

`kReferenceBlendCapacity`, `kPrimaryControllerChannel`, and `kBehaviorSwitchCooldownFrames` are policy constants from the original contract. They are not Resynced memory layouts.

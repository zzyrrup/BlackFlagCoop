# BlackFlagCoop v0.6.4 — Deferred Actor Creation Handler

**Date:** 2026-11-12  
**Target:** AC Black Flag Resynced 1.0.6  
**Mode:** Offline PE only  
**ASI:** v0.5.1 preserved (`63B38877…`)  
**EXE:** `19920F34…`

## Executive verdict

`0x1AC380` is the **registered** `CreateActorsDeferredSingleThreaded` handler (LEA at `0x5CBE0DE` confirmed). It is a **deferred work-queue processor** over a 16-byte element array on a coordinator object — **not** a proven character/Edward factory.

`0x7B00B60` and `0x29C6910` have **no call/data-flow link** to `0x1AC380` beyond sharing the phase registrar. Action vtable `0x9255320` is installed by descriptor constructors; **no verified input→character path**.

## Workstream A — Handler `0x1AC380`

### Boundary (confirmed)

| Field | Value |
|-------|-------|
| Entry | `0x1AC380` |
| End | `0x1ACA4A` |
| Size | **1738** bytes (`0x6CA`) |
| Section | `.impdata` |
| Method | RET then INT3 run |

Prologue saves non-volatiles, `sub rsp,0x70`, spills XMM6–8, **`mov rsi, rcx`**.

### Arguments / object model (confirmed)

1. `rcx` = owner/coordinator object → `rsi`.
2. Load nested pointer `[rcx+0x190]`; **early-out if null**.
3. Deferred array:
   - base `[rsi+0xAC0]`
   - count `[rsi+0xAC8] & 0x3FFF`
   - **stride 0x10**
4. Capacity asserts reference:
   - `"Too many elements for %sArray. Size: %u, Max Size: %u"`
   - `"Small"`

### Control flow (confirmed)

- ~56 conditional branches, ~22 backward-jump loop hints.
- **Pass 1:** walk elements; AVX/SSE float work at **element+8**.
- **Pass 2:** for each element:
  - `call 0x725400(elem, dl=1)`
  - `call 0xE95E80(elem)`
- Also hits allocator-validator `0x44FCD00`, SSO helper `0x53519E0`, security check `0x5014570`.

### Callers (confirmed absence of direct E8)

- No direct `E8` callers and no absolute qword pointers to entry.
- Invocation path: **phase function pointer** installed by registrar `0x5CBDFB0`.

### What it does **not** show

- No Edward / character / archetype / player / transform / anim strings in-function.
- No confirmed entity allocation or component construction inside the handler body.
- Element records are **untyped** at this level (16 bytes + float@+8).

**Confirmed role:** deferred queue/array drain with per-element follow-up calls.  
**Hypothesis (not confirmed):** elements are pending actor/job handles and `0xE95E80` finishes creation/activation.

### `0x7B00B60` — UpdateActorControllersSingleThreaded (identity)

- Size ~299 bytes.
- Loads list `[rcx+0x98]`, count masked `0x3FFF`, walks entries (~0x18 stride).
- Clears flag `[list+0x15B]`; matches magic `0x8365D591` at entry+8.
- **Role:** controller-list update/dispatch — **not creation**.

### `0x29C6910` — UpdateActorSingleThreaded (identity)

- Size ~260 bytes.
- TEB TLS (`gs:[0x58]`); lazy-allocates **0xC** via `0x426EE50`; sets a TLS flag.
- **Role:** **per-thread TLS bootstrap stub** for the named phase — **not** an actor loop or factory.

## Final report answers

1. **What does `0x1AC380` do?**  
   **Confirmed:** drains a deferred 16-byte-element array on a coordinator (`+0xAC0`/`+0xAC8`), runs float work, then per-element calls `0x725400`/`0xE95E80`.

2. **Create or initialize entities?**  
   **Not confirmed.** Queue processing yes; entity/actor allocation not proven in this function.

3. **Connected to character creation?**  
   **No verified connection.**

4. **Edward archetype reuse?**  
   **Unsupported** by current evidence.

5. **`0x7B00B60` / `0x29C6910`?**  
   Unlinked to handler. Controllers = list walk/update. UpdateActor stub = TLS lazy init.

6. **What consumes action descriptors?**  
   Constructors install vtable `0x9255320`; methods include ManagedObject/Stick-related code. Gameplay dispatch untraced.

7. **Verified input→character connection?**  
   **No.**

8. **Strongest evidence for multiple character actors?**  
   Multi-entry deferred queue + multi-actor phase registration — **infrastructure only**.

9. **Next safest second-Edward step?**  
   Offline analysis of **`0xE95E80`** / element layout — still no live tests or spawning.

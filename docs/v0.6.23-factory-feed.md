## Discovered

### Confirmed — TypeInfo layout reminder

| Field | RVA | Offset from key |
|-------|-----|-----------------|
| LookupKey / ti base | `0xB2898C8` | +0 |
| Size dword | `0xB2898E8` | +0x20 (= `0x20F0`) |
| Ctor qword | `0xB289918` | +0x50 (`0x59D9660`) |

LEA census: **key=170**, **sizeFld=0**, **ctorFld=0** (InstallerA writes size/ctor; no absolute readers — matches v0.6.21).

### Confirmed — no tight-factory caller feeds this TypeInfo (offline)

| Probe | Result |
|-------|--------|
| Tight-factory caller records | **186** |
| Callers LEAing LookupKey | **0** |
| Callers with imm `0x20F0` | **0** |
| Key-func ∩ factory-caller | **0** |
| Key funcs with Lookup+Alloc but **no** tight factory | `0x1B6AFF0`, `0x26D28E0`, `0x2F2C1A0` |

**Confirmed:** none of the E8/LEA callers of the five tight factories offline-prove supplying TypeInfo for key `0xB2898C8` / size `0x20F0`. Those key-tied Lookup+Alloc sites use **alternate** alloc paths (already rejected as tight factories in v0.6.22).

**Hypothesis (not verified):** some caller obtains this TypeInfo at runtime (field/cache) and passes it into a tight factory without a RIP key LEA in the same function — not recoverable as a unique feed offline without live memory.

### Confirmed — possession-like helper deep-decode

Decoded **32** `0x546D150` caller funcs (all unique callers). Signals:

| Entry | Role | Finding |
|-------|------|---------|
| `0x2335140` | neighbor-baseline | edx=3 `[vt+0x2B0]` then helper → `vmovups` into `+0x40…` (prior) |
| `0x2336560` | thin-wrapper (58 B) | helper → `[rax+30]` blend → store `[rsi]` — **position extract**, not possession |
| `0x1D25E20` | arm-neighbor-like / spatial | multi-helper matrix/spatial math (`vfmadd`/`vmovups` from helper return) — **transform LOD**, not input ownership |
| Others | mostly block-copy / sideblock-walker | Same family as neighbor’s transform copy |

Across decoded set: **keyLinked=0**, **factoryLinked=0**, **vcall2B0=2** (neighbor + `0x1D25E20` signal).

**Confirmed:** helper consumers examined here resolve/copy transforms; **not** proven as possession/control for a second Edward.

## Data flow that actually closes

```
copy(src, optionalDest, mode)
  dest = optionalDest, or pool-pop from the type global
  copy +0x58 and +0xA8
  player/boat only: copy a short tail
  return dest
```

Nothing after that return is connected to a world, entity, or enqueue receiver. Calling this a spawn would be wrong.

NPC and player share that protocol. NPC-specific state is the type global `0xB5378F0`, hash `0x94D05600`, and a copy with no tail. Player-specific state is type global `0xB537FC8`, hash `0x51BA3541`, and the `+0xC0` / `+0xB0` tail. `SpawnPlayerParams` stays the existing player type.

## AC4Coop

Kamzik123's AC4Coop, as described in the Universal Modder field notes, builds a second body on **32-bit `AC4BFSP.exe`** from the local player's cached `EntityBuilder` (`BuildEntityWithSelector`, then `World::AddEntity`, plus `GetUnusedPadID`). `RowSelector::Duplicate` is only valid inside `DuplicationManager`. Those addresses are for that exe.

In this Resynced image the strings `BuildEntityWithSelector`, `BuildEntity`, `GetUnusedPadID`, `DuplicationManager`, `RowSelector`, `World::AddEntity`, and `EntityBuilder::` occur **zero** times. The reflected params family is not that API, and that API's names are not in this binary. Do not copy AC4Coop RVAs here.

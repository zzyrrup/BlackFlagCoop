## Discovered

### Confirmed — VT`[+0x20]` construct is vcall-only

| Check | Neigh `0x3D52400` | Spat `0x6CF34E0` |
|-------|-------------------|------------------|
| E8 callers | **0** | **0** |
| LEA sites | **0** | **0** |
| FF15 to slot | **0** | **0** |
| Qword embeds | 1 (`VT+0x20` slot only) | 1 (`VT+0x20` slot only) |

Generic `call [rax+0x20]` exists widely (**4659** sites / **3166** funcs) but cannot be typed to Neigh/Spat offline (no RTTI / no static VT compare in top annotated set).

Owner VT LEAs are **installers** (VT0/SpatA/SpatB/NeighRel), not `+0x20` callers.

**Confirmed:** Neigh/Spat construct-from-TI methods are **table-dispatched only**.

### Confirmed — three `+0x98` consumer families + Neighbor bridge

| Family | Pattern | Exemplars |
|--------|---------|-----------|
| **Byte** | `mov/cmp byte [reg+98]` | NeighRel zero-init; Neighbor `this+0x98` flag |
| **Pointer** | qword load/store/`cmp qword …,0` | SideBlock, Arming, ArmWrap, Helper546 |
| **Spatial inline** | `add/lea reg,98` | SpatVt0 / SpatA / SpatB / SpatVt20 |

**Neighbor bridge `0x2335140`** (Neigh VT`[+0x110]` @`.edata 0x976B3E0`, E8=0):

1. `or [this+0x23],1`; if `edx∈{2,3}` → `vcall [vt+0x2B0]` with `edx=3`.
2. `nested=[this+0x18]`; **pointer** load `[nested+0x98]` (pointer-family on nested).
3. Copy transforms nested→this; **`mov byte ptr [this+0x98],1`** (byte-family on this).

**Confirmed:** Neigh-method `this` uses the **byte** `+0x98` layout (same family as size-`0xB0` NeighRel). Enrollment **pointer** `+0x98` lives on a **nested** object at `this+0x18`, not on the Neigh object itself.

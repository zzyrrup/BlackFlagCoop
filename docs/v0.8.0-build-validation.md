## What this change registers

`cmake/bfc_offline_tests.cmake` adds:

| CTest name | Command | Timeout |
|------------|---------|---------|
| `NetDiagSelfTest` | `BlackFlagCoopNetTest --diag-self-test` | 30s |
| `NetSelfTest` | `BlackFlagCoopNetTest --self-test --port 27116` | 60s |

Both are labeled `offline;no-game;no-deploy`. `NetSelfTest` takes a resource lock on its port. It binds localhost and can fail if `27116` is already in use. It was not executed here. Neither test launches Assassin's Creed or copies an ASI.

CI (`.github/workflows/offline-validation.yml`) runs the Python unit tests and the static audit on `ubuntu-latest`. It does not invoke the Visual Studio generator. Hosted runners were not verified to have Visual Studio 18 2026, so a Windows job would only add a red check.

## Repeatable checklist

Run this on a Windows x64 machine with Visual Studio 18 2026 and CMake 3.20+. From the repo root:

1. Record the commit and confirm the tree you intend to validate.

   ```powershell
   git rev-parse HEAD
   git status --porcelain
   ```

2. Leave the installed ASI in place. A read-only comparison, if you want one, is:

   ```powershell
   Get-FileHash "C:\Games\AC Black Flag Resynced\BlackFlagCoop.asi" -Algorithm SHA256
   ```

   Expected v0.5.1 hash: `63B38877DDA7CC7CD9AB2619F94D3941C37F54C95A435EFE47084DC4CF2A50BE`. Do not copy a new ASI over that file. The recorder refuses candidate paths outside `<repo>\build` and refuses a `Games` or `AC Black Flag Resynced` path.

3. Configure, build, and test. Keep the logs.

   ```powershell
   cmake -S . -B build -G "Visual Studio 18 2026" -A x64 *> reports\v0.8.0-cmake-configure.txt
   cmake --build build --config Release *> reports\v0.8.0-cmake-build.txt
   ctest --test-dir build -C Release --output-on-failure *> reports\v0.8.0-ctest.txt
   ```

4. Run the recorder. It writes only under `reports\` and forces `deploymentStatus` to `not_deployed`.

   ```powershell
   python scripts\record_offline_validation.py --repo . `
     --configure-log reports\v0.8.0-cmake-configure.txt `
     --build-log reports\v0.8.0-cmake-build.txt `
     --ctest-log reports\v0.8.0-ctest.txt `
     --candidate-asi build\bin\Release\BlackFlagCoop.asi `
     --python-test-result pass
   ```

   Exit code `0` means the static audit, configure, build, and CTest all passed. Any other code means the JSON was still written and at least one of those steps did not pass. A passing CTest run does not mean the ASI was deployed or that co-op works in game.

5. Read these fields in `reports/v0.8.0-build-validation.json` before anyone treats the binary as a candidate:

   - `commit`, `branch`, `dirty`
   - `host.cmake`, `compiler.generatorRequested`, `compiler.architectureRequested`, `compiler.configRequested`
   - `configure.result`, `build.result`, `tests.ctest`
   - `candidateAsi.sha256`, `candidateAsi.bytes`, `candidateAsi.deployed`
   - `deploymentStatus` (`not_deployed`)
   - `installedAsi.modifiedByThisRun` (`false`)

6. Optional static check, including on a machine that cannot run MSVC:

   ```powershell
   python -m unittest discover -s tools\build_validation_test -v
   python scripts\audit_cmake_surface.py --repo .
   ```

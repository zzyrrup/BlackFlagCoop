## Discovered

### Confirmed — Spatial construction path (runtime TypeInfo)

| Step | Evidence |
|------|----------|
| Registrar | `0x5E5AF20` published at `.edata 0xA23E188` (E8=0) |
| Runtime fill | LEA SpatA `0x5563CF0` → store `.trace 0xACE8448`; LEA SpatB `0x6CF34A0` → store `.trace 0xACE84C8` (fields **zero in PE**, filled at runtime) |
| VT install | SpatVT0 / SpatA / SpatB all `lea SpatVT; mov [rcx], vt` |
| Invoke | Generic tight-factory `icall [ti+0x50]` once TypeInfo ctor field points at SpatA/SpatB, **or** `call [vt+0]` |
| Meta link | Spat VT`[+0x30]` → `0xACE83F8` (.trace region near ctor fields) |

**Confirmed:** Spatial objects are constructed by **SpatA / SpatB / SpatVT0** (in-place VT install). SpatA/SpatB are **runtime-registered** into TypeInfo-like `.trace` fields by SpatRegistrar — closing the static “no ti+0x50” gap from v0.6.27 for Spatial.

### Confirmed — Neighbor construction path (table-only; no runtime registrar found)

| Step | Evidence |
|------|----------|
| VT install funcs | Only `NeighVT0 0x13612B0` and `NeighRel 0x3D522C0` LEA Neigh VT |
| NeighRel publish | PE-static qword `@0xAAD22E0 = 0x3D522C0` (not zeroed / not runtime-filled like Spat fields) |
| Runtime TypeInfo registrar | **Not found** (no SpatRegistrar equivalent writing Neigh ctor fields) |
| Meta link | Neigh VT`[+0x30]` → `0xAAD2290` (near NeighRel slot) |
| Invoke | Table / `call [vt+0]` only (E8=0 to both) |

**Confirmed:** Neighbor VT install sites identified; **no** recovered runtime TypeInfo registration path equivalent to Spatial.

**Date:** 2026-11-12  
**Working ASI:** v0.5.1 (unchanged; not deployed)  
**Scope:** plugin TCP session reliability only (localhost-tested)

## Safety

- No game launch, ASI deploy, injection, or live memory access  
- Framing for messages 1–7 preserved; type 8 remains additive  

## What changed

| Piece | Behavior |
|-------|----------|
| `ReliabilityConfig` | Optional; `enabled=false` by default |
| Defaults | `heartbeatIntervalMs=5000`, `idleTimeoutMs=30000` |
| `Session::Poll` | Send heartbeat if due; consume valid heartbeats; detect idle timeout |
| `Session::Receive` | Still works; refreshes inbound activity on valid messages |
| Heartbeats | Do **not** touch `PlayerStateTracker` pose/movement |
| Malformed heartbeat | `ParseHeartbeat` fails → `Poll` returns `Rejected`; session stays Active |
| Timing | `std::chrono::steady_clock` (monotonic); waits via `Network::Receive` timeouts (no busy-wait) |

## Idle disconnect semantics

- **Silent peer:** no *valid* inbound framed message for `idleTimeoutMs` → `SessionPollResult::IdleTimeout`, session reset, `IdleTimedOutFlag()==true`  
- **Clean disconnect:** `Leave()` / peer socket close → Idle / Disconnected **without** idle flag when Leave is local  
- Heartbeat interval `0` disables outbound heartbeats (useful to simulate a silent peer in tests)  
- Production guidance: keep `idleTimeoutMs >= 2 × heartbeatIntervalMs` (warning logged if not)

## Compatibility

- Handshake (1–2), ping/pong (3–4), presence (5), state (6), state-ex (7) unchanged  
- Peers that ignore unknown types remain compatible with heartbeat senders  
- `poseVerified` sanitization from overnight work retained and covered by `--diag-self-test`

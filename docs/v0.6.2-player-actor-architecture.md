## Final answers

1. **How is the active player character represented?**  
   **Unknown** offline. No `LocalPlayer` / controller type recovered.

2. **What code creates character actors?**  
   **Not identified.** Only a deferred-create **phase label** with a weak RIP ref.

3. **What initializes/activates them?**  
   **Not identified.**

4. **How does input reach the active character?**  
   Action **names** exist (`Pad_*`/`Key_*`). One RIP lead to `Pad_LockAndTurnMovement` (`0x187F0558`). Binding from action → actor **untraced**.

5. **Is ownership separate from actor existence?**  
   **Unknown** — no possession layer found.

6. **Evidence for two simultaneous Edwards?**  
   **None.**

7. **Biggest blocker?**  
   No mapped **player-actor factory**, **ownership/possession**, or **input→actor** binding.

8. **Safest next experiment?**  
   Offline deepen **`0x187F0550` / `0x187F0558`** (`Pad_LockAndTurnMovement` consumer) and **`0x5CBDFB0`** (deferred-create phase string user) call graphs — character-scoped only; **still no spawn**.

## Discovered

### Confirmed — no static TypeInfo/`+0x50` binding to owner VT[0]

| Probe | Result |
|-------|--------|
| Qword embeds of VT[0] ctors | **Only** at VT bases `0x976B2D0` / `0x9236E00` |
| LEA of ctor addrs (InstallerA-style register) | **0** |
| `movabs` ctor imm64 | **0** |
| Store ctor into `[reg+0x50]` | **0** |
| Non-VT “TypeInfo-shaped” `+0x50=ctor` hits | **0** |

**Contrast (Outer path still works offline):** Outer ctor `0x59D9660` has **LEA×2** registration sites (InstallerA-style). Owner VT[0] has **no** equivalent static registration.

**Generic `[ti+0x50]` consumers (not owner-tied):** tight factories `0x238590` / `0x256280` / `0x218900` / `0x218660` / `0x21FA70` each `Allocator` + `icall [ti+0x50]`. Offline, none of these are bound to owner VT[0] ctor pointers in the PE image.

**Confirmed:** owner VT[0] is **vtable-slot only** in static PE (not a recovered TypeInfo ctor field).  
**Hypothesis:** runtime/reloc TypeInfo fill, or an outer/factory ctor that installs the VT then returns — not visible as static `[ti+0x50]=VT[0]`.

### Confirmed — pointer `+0x98` vs Spatial inline `+0x98` are distinct

| Class | Functions | Pattern |
|-------|-----------|---------|
| **pointer** | SideBlock `0xE95E80` (store+load), Arming `0x21085D0` (cmp), ArmWrap `0x2108620` (load), Neighbor method `0x2335140`, NeighRelated `0x3D522C0` (store), Helper `0x546D150` (load) | `mov/cmp [reg+98]` as **side-block pointer** |
| **inline** | Spat VT0 `0x5781490`, SpatInstA `0x5563CF0`, SpatInstB `0x6CF34A0`, Spatial method `0x1D25E20` | `add/lea reg, 98` then **subobject init call** |
| **mixed** | SpatInstC `0x6CF3750` | both `add …,98` and `mov […+98],…` |
| **none** | Neigh VT0 `0x13612B0`, queue `0x1AC380` | no direct `+0x98` in body (queue calls SideBlock) |

**Confirmed:** same numeric offset, **two layouts**. Arming/enrollment consume the **pointer** family. Spatial owner ctors primarily use the **inline** family. Do not conflate them.

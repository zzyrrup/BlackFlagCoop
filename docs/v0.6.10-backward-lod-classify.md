**Highest-signal depth-0 allocator+nested+lookup nodes:**

| Entry | Nested | Lookup | Alloc | Imm sizes (sample) |
|-------|--------|--------|-------|--------------------|
| **`0x400B50`** | yes | yes | **yes** | `0x50`, `0x1C8` |
| **`0x4444C0`** | yes | yes | **yes** | `0xE0`, `0x100`, `0x1C8` |

Other allocator hits appear at depth 1–2 via lookup callers (e.g. `0x24090`, `0x3F710`) or further callees — **not** proven as Edward factories. Side-block size `0x160` (worker B) did **not** dominate these allocator imm samples.

**Control:** deferred handler `0x1AC380` appears at depth 1 as an E8 caller of worker `0x725400` (expected). Phase registrar reaches LOD stub via LEA (`0x5CBE045`).

**Overlap with LOD consumers:** `0xAE3F0` (cmp installer; calls into nest seed `0xB12D0`) and registrar `0x5CBDFB0`.

### Confirmed — LOD consumer classes

| Class | Count | Meaning |
|-------|------:|---------|
| `cmp_only` | 16 | LEA-installs comparator into small bundles (`+0x8/+0x10/+0x18/+0x20` typical) |
| `cmp_thunk_bundle` | 13 | Installs both cmp + thunk |
| `thunk_only` | 1 | Thunk without cmp in analyzed window |
| `generic_bundle_installer` | 4 | Prior LEA site; no cmp/thunk LEA in func window (false pairing / tiny) |
| `phase_registrar` | 1 | **`0x5CBDFB0`** — only analyzed func with **stub+cmp+thunk** and stores at **`+0xE10/+0xE18/+0xE20…`** |

**Verdict:** Only the **phase registrar** builds the UpdateActorLOD-style bundle that includes stub `0x1A5A70`. Other consumers reuse cmp/thunk as generic callback-table entries — not Edward-specific.

### Hypothesis (not verified)

- `0x400B50` / `0x4444C0` may allocate/init objects that later enroll in LOD/queue via nested lookup — **unproven**.
- Object sizes `0x1C8` / `0xE0` / `0x50` may be related structures on that path — **not** confirmed as the queued subject.

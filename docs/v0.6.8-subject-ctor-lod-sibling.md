## Discovered

### Confirmed — LOD sibling `0x67BDB30`

| Item | Value |
|------|-------|
| Entry | `0x67BDB30` |
| End | `0x67BDB50` (**32 bytes**) |
| Section | `.impdata` |
| Role | **Pointer comparator** on nested `[arg+8]` |
| Behavior | `mov rcx,[rcx+8]`; `mov rdx,[rdx+8]`; return **0** if equal else **±1** |
| Direct callees | none |
| E8 callers | **0** |
| LEA xrefs | many (phase/bundle registration stores; capped sample 40) |

**Not** the adjacent function at `0x67BDB50` (refcount/allocator helper). Earlier registrar pairing that listed `0x67BDB30` as a phase “handler” was a LEA-proximity false pairing; the UpdateActorLOD bundle stores it at **`coord+0xE28`** as a comparator, with thunk **`0x1A5A00`** at **`+0xE30`** (`mov rax,rcx; mov rcx,rdx; jmp [rax+8]`).

**Hypothesis (not verified):** together these support ordered/unique tracking of wrapped pointers for LOD — not actor creation.

### Confirmed — subject fingerprint / constructor scan

| Probe | Result |
|-------|--------|
| Field-use candidates (`+0x61` / `+0x98` / `+0x3CD0`) | 128 funcs (33 with `+0x61`, 31 with `+0x98`, 67 with `+0x3CD0`) |

| `or [reg+0x61],4` writers | Wrapper sites in `0x2E97FC0` (v0.6.6) + one extra site `0x1D7AD9CC` (not proven related) |
| Strong combo (`+0x61` and `+0x98`) | **`0x1D9CC0`** (aligned LEA installs, **no** MSVC RTTI) |
| Top `+0x61` writers with many LEA installs | `0x519E20`, `0x2D4F30` (zero `+0x61`; clear flag/init patterns) |
| MSVC RTTI on candidate vtables | **none recovered** |
| `.?AV*` type strings matching Actor/Edward/Character/Entity/Player/LOD | **0** |

**MSVC RTTI availability (image-wide):** only ~37 `.?AV` names exist; samples are CryptoPP/STL (`Exception@CryptoPP`, `bad_alloc@stdext`, …). Game/Anvil types appear **stripped** of MSVC RTTI — offline COL-name recovery for subjects is blocked on this build.

### Hypothesis (not verified)

- `0x519E20` / `0x2D4F30` / `0x1D9CC0` may be large object initializers that touch a flag at `+0x61`, but none are proven as the deferred-queue subject type or Edward.
- LOD comparator implies subjects are identity-comparable via an inner `+8` pointer — consistent with wrapped handles, not a factory.

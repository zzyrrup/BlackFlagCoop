## 3. Puppet lifecycle (ordered)

### 3.0 Threading invariant (applies to all steps)

| Item | Detail | Label |
|------|--------|-------|
| Rule | All engine create/drive/remove runs on the **game main thread** inside a per-frame Human-update detour | source-confirmed (`phase1.h` L5–7; `OnFrame` @ `phase1.cpp` L1013+) |
| Hotkeys | F6/F7 only set volatile request flags; execution waits for next player Human update | source-confirmed (`RequestSpawn` L1262; `OnFrame` L1115) |
| Filter | Hook fires for every Human; work runs only when `AIEntityHelper::GetHuman(player) == updatedHuman` | source-confirmed (`isPlayerUpdate` L885–896) |
| Failure | Spawning/driving off the main thread → pool/scheduler corruption | author-documented (`phase1.h`) |

## 6. Failure modes & invariants (summary)

| Invariant | Failure if broken |
|-----------|-------------------|
| Main-thread only for spawn/drive/despawn | Allocator / scheduler crashes |
| Duplicate always inside Begin/End | Permanent duplication corruption |
| Build consumes selector → must Duplicate first | Use-after-free / null selector |
| Distinct pad for puppet enrollment | Local player hijack |
| Single action writer | Crash on overlapping SetTargetAction |
| Persist blend factors + timeScale | Stuck walk / wrong gait |
| Clear `g_puppet` before RemoveEntity | Driving a dying entity |
| Do not transplant x86 layouts/addresses | Instant wrong-target on Resynced x64 |

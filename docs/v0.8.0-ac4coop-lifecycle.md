# v0.8.0 — AC4Coop puppet lifecycle

**Source:** https://github.com/Kamzik123/AC4Coop (`src/phase1.cpp`, Scimitar wrappers).  
**Target:** AC Black Flag Resynced 1.0.6, x64. Original x86 file addresses are not copied into this plugin.

## Source-confirmed sequence

`Phase1::TrySpawnPuppet` in `src/phase1.cpp` does this, on the main thread (`World::LinkUpdateAction` hook; the hotkey only queues the request — `src/phase1.h`):

1. `World::GetCurrentWorld`, then `World::GetPlayer`.
2. `PlayerProgression::GetCachedSelector` and `GetCachedBuilderHandle` (`src/Scimitar/PlayerProgression.h`). The comment there says `PlayerProgressionManager::LoadEntityBuilderAndSelectorsForPlayer` fills those globals when the local player spawns, and that the builder object may already have been released while the handle still holds the resource id.
3. If the builder object is gone, `reloadBuilder` reloads it by that id (`LoadingThread::AddLoadTask_Callback`).
4. `DuplicationManager::Begin(1, 0)`, `RowSelector::Duplicate(0, 0)`, `DuplicationManager::End` in a `__finally`. `src/Scimitar/DuplicationManager.h` says `BuildEntityWithSelector` consumes the selector, and `Duplicate` must run inside that scope.
5. `EntityBuilder::BuildEntityWithSelector(&entity, duplicatedSelector)`.
6. Integration is separate. With `Coop.IntegratePuppet=0` and networking off, the function returns the built entity and does not add it to the world.
7. Otherwise it sets `g_blockReg` so `BhvAssassin::AddToWorldInternal` will not enroll the puppet on the local pad (`MyGetUnusedPadID` in `phase1.cpp`), then `World::AddEntity`.
8. `Entity::SetPosition` at the player position plus a 2 m offset.
9. `PlayerPadManager::RegisterPlayer(entity, 1)` only when networking is off and `RegisterPad1` is set. A networked puppet is not given a pad.
10. Later frames: `Phase1::ApplyRemoteState` calls `Entity::SetGlobalMatrixInternal`, toggles the behavior component, and may call `ActionComponent::SetTargetAction`. That driving is not part of the first build.
11. `Phase1::DespawnPuppet` clears the puppet pointer, then `World::RemoveEntity`.

`src/phase1.h` states engine construction is only safe on a thread the engine initialized.

## README versus source

The README says the puppet spawns, despawns, and plays actions. Those are claims about the x86 mod. The sequence above is what the source actually calls. This repository has not reproduced that sequence on Resynced.

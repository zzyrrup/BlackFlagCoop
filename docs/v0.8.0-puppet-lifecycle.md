## What shipped

An offline state machine for one remote puppet: creation bookkeeping, visibility, pause preservation, peer-absence grace, world-drop versus explicit remove, disconnect, and teardown. Engine operations go through `EngineOps`. Unless a test calls `AllowScriptedOpsForTests(true)`, those methods are never invoked. The machine then refuses the spawn and does not report a drive handle or a visible puppet.

`ClaimsLocalPad()` is always false. This machine does not enroll a pad, write a transform, or play an action.

## AC4Coop lifecycle (source-confirmed)

Labels: **source-confirmed** means the cited function does it. **author-documented** means a comment or README. **hypothesis** is not used as a Resynced fact. x86 addresses in the wrappers are not repeated here.

### Threading

`phase1.h` lines 5–7 say construction is only safe on an engine thread, and they name `World::LinkUpdateAction`. `phase1.cpp` lines 43–47 say that site was wrong: the installed hook is the per-frame Human update. `OnFrame` (`phase1.cpp` 1013–1115) returns immediately unless the updated Human is the local player's (`isPlayerUpdate`, 885–896). Hotkeys only set `g_spawnReq` (`RequestSpawn`, 1262); the frame hook consumes it (1115).

### Spawn order (`Phase1::TrySpawnPuppet`, 249–360)

1. `World::GetCurrentWorld`, then `World::GetPlayer` (252–258). Either missing aborts.
2. `PlayerProgression::GetCachedSelector` and `GetCachedBuilderHandle` (261–263). The header (`PlayerProgression.h` 7–10) says those globals are filled when the local player spawns, and that the builder object may already have been released while the handle keeps the resource id.
3. If the builder object is unreadable and an id is known, `reloadBuilder` (207–227) calls `LoadingThread::AddLoadTask_Callback` and polls up to 200 times with `Sleep(10)`. **source-confirmed** asynchronous wait. `LoadingThread.h` 5–7 describes it as the rare reload path.
4. `DuplicationManager::Begin`, `RowSelector::Duplicate` inside `__try/__finally`, then `DuplicationManager::End` (294–302). `DuplicationManager.h` 5–9 says skipping `End` leaves the scope unbalanced and corrupts later duplications. The comment at 296–297 names a stale selector after world travel as the fault case.
5. `EntityBuilder::BuildEntityWithSelector` runs **after** `End` (307–309). A failed or unreadable entity aborts before world integration.
6. If networking is off and `Coop.IntegratePuppet` is 0, the function returns the built entity and does not add it to the world (321–328).
7. Otherwise it sets `g_blockReg` so pad enrollment can be forced off the local pad, then `World::AddEntity` (334–337). The comment says Add is a deferred engine command processed next frame. `World::AddEntity` / `RemoveEntity` are the wrappers at `World.cpp` 14–21.
8. `Entity::SetPosition` at the local player plus a 2 m offset (341–343).
9. `PlayerPadManager::RegisterPlayer` runs only when networking is off and `RegisterPad1` is set (345–352). A networked puppet is not given a pad.
10. `g_puppet` is assigned only after that integrate block (354). An exception before that assignment does not publish the pointer (355–358).

### Per-frame policy (`OnFrame`, 1044–1112)

- `engineLoading()` (1005–1009) reads `LoadingManager::IsLoading` (`LoadingManager.h` 5–6) and blocks spawn and drive. It does not by itself remove a live puppet.
- Peer present means a fresh same-world packet within 2000 ms (1031–1042). A stale last packet does not count.
- If `g_puppet` is set and its vtable is unreadable or changed, the code drops the pointer and does **not** call `RemoveEntity` (1055–1064). It sets `g_spawnCd = 180` so the new world's builder can settle. Comment: a world change frees the entity; a pause leaves the vtable intact.
- If the vtable is intact and local capture fails, grace is cleared and the puppet is kept (1066–1067). Capture fails for a missing world, white room, or missing player (`CaptureLocalState` 365–377), which covers pause, menu, and white room. There is no separate "Edward died" transition.
- If capture succeeds and the peer is present, grace is cleared (1068–1069).
- Otherwise grace increments. When `++despawnGrace > 180`, `DespawnPuppet` runs (1070–1072).
- Spawn runs only when capture is ok, the peer is present, `stable > 60`, and the engine is not loading (1080). Cooldown uses `if (g_spawnCd > 0) --g_spawnCd; else attempt`, and each attempt sets `g_spawnCd = 120` (1082–1088). The frame that decrements the counter to zero does not also attempt.
- `stable` increments on successful capture and resets only when capture fails (1024–1026). Loading does not reset it.

### Despawn (`Phase1::DespawnPuppet`, 852–875)

Clears `g_puppet` and the pad-block marker **before** `World::RemoveEntity`. Comment 852–854: Remove is the deferred counterpart of Add, and nothing may drive the entity after removal is requested. Action, behavior, and character-action-set edge state is cleared so the next puppet reinitializes (860–864). A second call with a null puppet returns immediately (856).

`DLL_PROCESS_DETACH` (`dllmain.cpp` 181–183) sets `g_run = false` and does not call `DespawnPuppet`. **source-confirmed gap.** This machine's `Shutdown()` is an explicit teardown the upstream detach path does not perform.

### Death, respawn, world travel

`phase1.cpp` 96–100 and 1196–1230 discuss death, fast-travel, and respawn only as times when the **local player is absent**, so ambient `SpawningRequest::Spawn` suppression must not run or the load hangs. That is not a puppet-death handler. Puppet respawn after a world change is the vtable-drop path plus the 180-frame settle, then `TrySpawnPuppet` again. Peer disconnect and "peer left our world" share the grace-then-`DespawnPuppet` path (1070–1071). There is no separate disconnect RPC in this function.

## Machine

`bfc::puppet::RemotePuppetLifecycle` (`src/coop/remote_puppet_lifecycle.*`).

One instance, one peer. The drive handle is the only handle a later transform or action writer would read. `pendingRemoval` is not drivable. Generation increases when a build is actually issued and is not reused. `NotifyEntityFreed` / `NotifyOp` with the wrong generation are ignored.

Default `EngineOps` bodies return `Refused`. With scripted ops off, `Invoke` does not call the virtuals at all.

Duplication order, when a test enables scripted ops: `BeginDuplication`, `DuplicateSelector`, `EndDuplication`, then `BuildEntity`. `End` runs after a successful `Begin` even when duplicate fails. If `End` itself fails, `duplicationBalanced()` latches false and build is not called. The scope is not held across frames (`duplicationDepth()` is 0 after every public call in the tests).

Add failure, integrate timeout, and a refused add after a scripted build discard the unintegrated handle and do **not** call `RemoveFromWorld`. `leakRisk()` stays set: there is no proven destroy for an entity that was never enrolled. `RemoveFromWorld` is only requested for a handle that was accepted into the world (drive or integrating).

`Shutdown` is idempotent. A second call does not issue a second remove. If remove was refused or failed, phase `TornDown` still reports `removalConfirmed() == false` and `leakRisk() == true`. `Reset` is refused while any handle or removal is outstanding.

Visibility: `PendingEnroll` on the tick `Add` succeeds (pointer stored immediately, matching `g_puppet = newEntity` in the same function as `AddEntity`), then `Visible` on a later non-loading tick. `Preserved` is pause/menu/failed capture with the entity still alive. Loading suppresses `driveAllowed()` and does not despawn.

Threshold defaults match the source inequalities: spawn when `stableFrames > 60`, remove when `grace > 180`, retry cooldown 120, world-settle cooldown 180. Tests lower them; the comparisons stay the same.

### Transition table

"Safe now" means the bookkeeping transition is implemented and covered by the offline test. It does not mean a Resynced entity was created. "Blocked" means the step needs a native primitive PR #29 has not proven. While that primitive is missing, the default machine takes the refused row and does not pretend the blocked row happened.

| From | Condition | To | Engine op | Status |
|------|-----------|-----|-----------|--------|
| Absent | `sessionAlive` | Waiting | none | Safe now |
| Waiting | session dropped | Absent | none | Safe now |
| Waiting | capture unstable, loading, peer not fresh, or `stableFrames <= 60` | Waiting | none | Safe now |
| Waiting | eligible, cooldown > 0 | Waiting (decrement) | none | Safe now. The tick that reaches 0 does not also build. |
| Waiting | eligible, builder or selector not ready, no resource id | Waiting | none | Safe now. Does not report success. |
| Waiting | eligible, builder missing, resource id known | Waiting, or AwaitingReload if the op returns Pending | `ReloadBuilder` | **Blocked.** Default refuses and stays Waiting. PR #29: cached builder handle and reload are not identified. |
| AwaitingReload | timeout or failed completion | Waiting | none | Safe now (abstract timer). The 200×10 ms poll is not run. |
| Waiting | eligible, builder ready | Waiting | `Begin` / `Duplicate` / `End` / `BuildEntity` | **Blocked.** Default refuses the whole sequence and calls nothing. |
| Building | completion Ok | Present, Integrating, or Unintegrated | `AddToWorld` only if integrate is on and the test double accepts it | Add is **blocked** on a proven world enroll. |
| Building | completion failed or timeout | Waiting | none | Safe now |
| Unintegrated | `integrate == false` | Unintegrated | none | Safe now. Hidden. Matches the build-only ini gate, not a rendered puppet. |
| Integrating | completion Ok | Present, visibility `PendingEnroll` | none on that completion | Bookkeeping safe. The enroll call itself is **blocked**. |
| Integrating | failed or timeout | Waiting | none | Safe now. Handle discarded, `Remove` not called, `leakRisk`. |
| Present | next non-loading tick, entity alive | Present, visibility `Visible` | none | Safe now as a flag. Not evidence the game drew anything. |
| Present | `engineLoading` | Present, drive suppressed | none | Safe now |
| Present / PeerGrace | `localCaptureOk == false`, entity alive | Preserved | none | Safe now. This is also the local-death shape while the puppet vtable would still be intact. |
| Preserved | capture ok and peer present | Present | none | Safe now. Does not call `Add` again. |
| Present | local world id changes, entity still alive | stays Present or follows capture/peer rules | none | Safe now. World id alone does not drop. Matches the pause-menu fix in `OnFrame`. |
| Present | entity not alive, or `NotifyEntityFreed` for the current generation | Dropped | none | Safe now. `Remove` is not called. Settle cooldown defaults to 180. |
| Dropped | settle cooldown elapses and prerequisites return | Waiting, then a later attempt | build, if ever | The drop is safe now. The new build is **blocked**. |
| Present | peer not fresh, grace not yet over the threshold | PeerGrace | none | Safe now |
| PeerGrace | `grace > peerAbsentGraceFrames` | Waiting if remove Ok, else RemovalBlocked | `RemoveFromWorld` | The grace decision is safe now. The remove call is **blocked** until PR #29 proves a world remove. Default clears the drive slot, does not call out, and reports remove unconfirmed. |
| any with an in-world handle | `PeerLeft` or session no longer alive | Absent, or RemovalBlocked | `RemoveFromWorld` | Same split. Explicit leave does not wait for grace. That is a deliberate difference from AC4Coop, which only infers absence. |
| Removing | completion Ok | Waiting, or TornDown if shutdown was requested | none | Safe now for the test double |
| Removing | entity freed before completion | Dropped | none | Safe now. Remove is not repeated. |
| RemovalBlocked | `Shutdown` | TornDown | none | Safe now. Does not retry remove. `removalConfirmed` stays false. |
| any without a handle | `Shutdown` | TornDown | none | Safe now. Idempotent. |
| Present | `Reset` | Present (refused) | none | Safe now |
| TornDown | `Reset` | Absent | none | Safe now. Generation is not reused. |

## Blocked on PR #29

Still refused, and still not proven for Resynced 1.0.6 x64:

1. Cached local-player EntityBuilder and RowSelector (the `NeedCachedBuilder` stop).
2. A duplication scope around selector duplicate.
3. A build that returns a second Human-like entity.
4. World add and world remove, including deferred enroll.
5. Evidence those calls are legal on the simulation thread this machine assumes.

Until those exist, do not call `AllowScriptedOpsForTests` from the ASI. A scripted `Ok` is a test double, not a spawn.

## Handoff

- **PR #29:** The intended seam is `bfc::puppet::EngineOps`. A proven Resynced add/remove should override that class and stay default-off. Please do not treat `RemotePuppetLifecycle` phase `Present` as a factory. `PuppetLifecycle::Tick` can keep refusing in parallel.
- **PR #28:** Source reading here agrees with the lifecycle section of `docs/v0.8.0-ac4coop-source-map.md`, including the `phase1.h` versus Human-update discrepancy and the "clear `g_puppet` before `RemoveEntity`" order. Detach does not despawn; `Shutdown` here is intentional extra bookkeeping.
- **Workstreams 3 and 4:** Drive is allowed only in `Present` with `driveAllowed()`. This machine does not apply matrices or actions. `Preserved` and loading clear that flag.
- **Workstream 5:** Pad enrollment is out of scope. `ClaimsLocalPad()` cannot become true.
- **Coordinator:** Root `CMakeLists.txt` gained an append-only test target. `docs/CHATGPT_HANDOFF.md` was left untouched because PR #28 and PR #29 already edit it.

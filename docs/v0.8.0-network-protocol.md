## 1. Confirmed v1 transport

Evidence is the source on `main`. The session panel displaying a roster is not evidence of a live peer.

### Framing (`src/network/network.cpp`)

Confirmed:

- One Winsock TCP connection. `Network` holds one listen socket and one peer socket.
- On-wire frame, little-endian: `uint32 type`, `uint32 payloadSize`, then `payloadSize` bytes.
- `kMaxPayloadBytes` is `16 * 1024 * 1024`. A larger receive closes the peer socket.
- `Send` requires `ConnectionState::Connected`. The transport does not inspect the message type.
- `SendRawBytes` writes caller bytes with no framing of its own.
- There is no checksum beyond TCP, no encryption, and no sequence number in the frame.

### Messages (`src/network/protocol.h`)

Confirmed:

| Type | Name | Payload |
|------|------|---------|
| 1 | Handshake request | magic `BFC1` (`0x31434642`), version `1` |
| 2 | Handshake response | magic, version, session id, assigned local id, assigned remote id |
| 3 | Ping | raw bytes, parsed as a string |
| 4 | Pong | raw bytes, parsed as a string |
| 5 | Player presence | magic, player id, join/leave |
| 6 | Player state | magic, player id, connection status, x/y/z, tick |
| 7 | Player state ex | state plus yaw, pitch, movement 0..7, flags, session id |
| 8 | Heartbeat | magic, sender tick |

`IsRecognizedMessageType` is true only for types 1 through 8. `ParsePlayerStateEx` clears `kStateExFlagPoseVerified` on receive. There is no peer display name, no capability bitfield, no disconnect message, no error message, and no action message.

### Session lifecycle (`src/network/session.cpp`)

Confirmed:

- Host player id is `1`. Client player id is `2`. `0` is invalid.
- Handshake requires magic `BFC1` and version exactly `1`. The host assigns the client local id `2` and remote id `1`.
- Handshake receive timeout is 10 seconds. Session id is mixed from process id, thread id, and `steady_clock`.
- `ReliabilityConfig.enabled` defaults to false. When enabled, the heartbeat interval is 5000 ms and the idle timeout is 30000 ms.
- A valid heartbeat counts as inbound activity and does not update `PlayerStateTracker`.
- A malformed heartbeat returns `SessionPollResult::Rejected` and leaves the session active.
- Any other unrecognized type returns false from `MessageCountsAsValidInbound`, so it does not refresh the idle timer.
- `Poll` can end the session with `IdleTimeout` or `Disconnected`. There is no explicit disconnect payload.

### What v1 does not provide

- Capability or version negotiation beyond an exact version match.
- A bound smaller than 16 MiB.
- Stale-packet handling. `tick` is carried and stored; an older tick still overwrites tracker state in `PlayerStateTracker::ApplyState`.
- Timestamps. Ordering is not defined for snapshots.
- A bounded error report.
- An action snapshot of any kind.
- Identity text. The panel names are local UI strings ("Player 1" / "Player 2"), not a peer protocol field.
- CTest registration. Coverage lives in `BlackFlagCoopNetTest --self-test` and `--diag-self-test`, which need Winsock.

## 2. v2 peer protocol

Magic is `BFC2` (`0x32434642`). Header version is `2`. App protocol version is `2`. The codec writes and reads explicit little-endian fields. It does not depend on packed-struct layout.

A v1 frame is `BadMagic` here. v2 type numbers are a separate space: v2 type `8` is unknown, and it is not parsed as a v1 heartbeat.

### Header (28 bytes)

| Offset | Field | Rule |
|--------|-------|------|
| 0 | `uint32 magic` | Must be `BFC2` |
| 4 | `uint16 headerVersion` | Must be `2`. Any other value is `UnsupportedVersion` and the stream is failed. |
| 6 | `uint16 flags` | Bit 0 = must-understand. Any other bit is `Malformed`. |
| 8 | `uint16 messageType` | `0` is `Malformed`. |
| 10 | `uint16 reserved` | Must be `0`. |
| 12 | `uint32 sequence` | Must be `>= 1`. `0` is `BadSequence`. |
| 16 | `uint64 sendTimeMs` | Sender clock in milliseconds. `0` means unspecified. |
| 24 | `uint32 payloadBytes` | Must be `<= 484`. Larger is `TooLarge` and consumes nothing. |

Total packet size is `28 + payloadBytes`, and the maximum packet is 512 bytes. The codec does not scan for a new magic after a bad length. The connection is failed.

`Decode` returns `NeedMoreData` until a full header and the declared payload are present. `DecodeExact` rejects bytes after that one packet (`TrailingBytes`). `FrameBuffer` reassembles chunks up to 1024 buffered bytes.

### Messages

| Type | Name | Body | Status |
|------|------|------|--------|
| 1 | Hello | version, min version, capabilities, slot preference, display name, build tag | Stable enough to implement |
| 2 | HelloAck | negotiated version, accepted capabilities, peer id, host id, session id, preference-overridden flag | Stable enough to implement |
| 3 | Heartbeat | `uint64 senderTick` | Stable enough to implement |
| 4 | Disconnect | reason 0..5 | Stable enough to implement |
| 5 | ErrorReport | code, related sequence, text | Stable enough to implement |
| 6 | TransformSnapshot | player id, movement, claim flags, x/y/z, yaw, pitch, tick | **Provisional data contract** |
| 7 | ActionSnapshot | player id, action id, schema version, 0..4 floats | **Unfrozen. schemaVersion must be 0** |

Hello identity is printable ASCII (`0x20`..`0x7E`), 1..24 bytes, with no leading or trailing space. The build tag is the same character set, 0..16 bytes. Error text is printable ASCII, 0..160 bytes. A longer error is `TooLarge`.

Disconnect reasons: `Unspecified`, `PeerLeaving`, `HostShutdown`, `IdleTimeout`, `VersionRejected`, `ProtocolError`.

Error codes: `VersionMismatch`, `MalformedPacket`, `UnsupportedCapability`, `PayloadTooLarge`, `BadIdentity`, `UnexpectedMessage`, `SchemaNotFrozen`, `ProtocolFault`.

Movement values `0`..`7` match the v1 names Unknown, Idle, Walking, Running, Sprinting, Climbing, Swimming, Sailing. Any other value is `Malformed`. Floats must be finite. NaN and infinity are `Malformed`.

### Negotiation

Hello carries `protocolVersion` and `minCompatibleVersion`.

- Both must be non-zero, and `minCompatibleVersion <= protocolVersion`.
- The peer is compatible when `protocolVersion >= 2` and `minCompatibleVersion <= 2`.
- Negotiated version is always `2`. This codec has no v1 fallback.
- A peer whose minimum is above `2` is `Incompatible`.

Capability bits:

| Bit | Meaning | Class |
|-----|---------|-------|
| 0 | Heartbeat | Required |
| 1 | Error report | Known |
| 2 | Transform snapshot | Known, provisional payload |
| 3 | Action snapshot | Known, unfrozen payload |
| 4..15 | Reserved optional | Ignored |
| 16..31 | Reserved critical | `Incompatible` if set |

Accepted capabilities are the intersection of the two offers and the known mask. Heartbeat must survive that intersection. The host's `HelloAck.acceptedCapabilities` is that intersection. The client rejects an ack that grants a bit it did not offer, omits heartbeat, or sets a critical bit.

### Slots and identity

`AssignSlots` always returns host id `1` and peer id `2`. Those are the same numbers as `kHostPlayerId` and `kClientPlayerId` in `session.h`. A Hello that prefers slot `1` is accepted, `preferenceOverridden` is set, and the peer still receives slot `2`. The remote peer cannot take the host slot through this packet.

Display name and build tag are labels for logs and a future UI. They are not an in-world Edward and they are not a pad binding.

### Sequencing, time, and stale packets

Each message type has its own sequence space. A heartbeat at sequence 1 and a transform at sequence 1 are both fresh. Gaps are allowed so a later unreliable transport can drop packets. A sequence less than or equal to the last accepted sequence for that type is `Stale`.

Stale heartbeats do not refresh liveness. Stale transforms and actions do not replace the last snapshot. The session stays open.

`sendTimeMs` never overrides sequence order. When both the previous accepted time and the new time are non-zero and the new time is smaller, the packet still applies if its sequence is newer, and `timestampRegressed` is set. A zero timestamp is unspecified and does not move the stored timestamp.

### Compatibility

| Input | Result |
|-------|--------|
| Short buffer | `NeedMoreData`, phase unchanged |
| `BFC1` magic | `BadMagic`, stream failed, no error packet (the peer is not speaking v2) |
| Header version other than 2 | `UnsupportedVersion`, stream failed |
| Unknown type, flag clear | `UnknownIgnored`, phase unchanged |
| Unknown type, must-understand | `MustUnderstandRejected`, phase `Failed`, error packet if the error capability is offered |
| Declared payload above 484 | `TooLarge`, nothing consumed |
| Extra bytes after one packet in `DecodeExact` | `TrailingBytes` |
| Action `schemaVersion != 0` | `SchemaNotFrozen`, snapshot is not stored |
| Transform claim bit 0 | Decode succeeds, bit is cleared, `verifiedClaimStripped` is set |
| Transform claim bit other than 0 | `Malformed` |
| Encode of a verified-pose claim | Refused |

Eight protocol faults (malformed frames, unnegotiated payloads, schema refusals, or inbound errors) move the session to `Failed`. One inbound `VersionMismatch` error fails it immediately. Unknown-ignored packets and stale packets do not spend the budget.

### Session machine

`SessionMachine` is an in-memory lifecycle. It has no socket and no engine call. `Start` / `HandleDatagram` / `Leave` are the only transitions.

| Phase | Event | Next | Outbound |
|-------|-------|------|----------|
| Idle | Host `Start` | WaitHello | none |
| Idle | Client `Start` | WaitHelloAck | Hello |
| WaitHello | Compatible Hello | Open | HelloAck |
| WaitHello | Incompatible Hello | Failed | Error, when offered |
| WaitHello | Disconnect | Closed | none |
| WaitHelloAck | Compatible HelloAck | Open | none |
| WaitHelloAck | Disconnect | Closed | none |
| WaitHelloAck | Error | Failed | none |
| Open | Fresh heartbeat, transform, or action inside the accepted capabilities | Open | none |
| Open | Stale snapshot or heartbeat | Open | none |
| Open | Hello or HelloAck | Failed | Error |
| Open | Fresh Disconnect | Closed | none |
| Open or handshake | `Leave` | Closed | one Disconnect |
| Closed | Further packets or `Leave` | Closed | none |

The machine assigns sequence numbers for its own Hello, HelloAck, Error, and Disconnect packets. Snapshot and heartbeat sequences belong to the sender that calls `Encode*`. That split matches the per-type sequence spaces.

`HelloAck.assignedPeerPlayerId` is the id of the Hello sender (slot 2). `HelloAck.hostPlayerId` is slot 1. From the client's point of view that is local id 2 and remote id 1, the same assignment v1 puts in `HandshakeResponsePayload`.

### Isolation invariants

These are enforced by the codec and covered by tests:

- A decoded transform stores `claimFlags == 0`. The wire may set the verified-pose bit; the codec clears it and reports that it did so. `EncodeTransform` refuses a non-zero claim.
- A decoded action has `mayApplyToLocalInput == false`. `MayApplyActionToLocalInput` returns false for every snapshot.
- Action schema version 0 is a placeholder. The action id is an opaque integer. This lane does not interpret it as an engine input, a pad slot, or an animation.
- Slot assignment cannot move the host off player id 1.
- No function in this codec calls the game, Winsock, or the v1 `Network` class.

Transform and action payloads are plain data. They are not a claim that a second Edward exists, that a pose came from the game, or that co-op replication works.

## 5. Integration questions for the coordinator

1. **Action schema.** `schemaVersion` stays `0` until an owner publishes the action id list. Please have the input/pad lane and the puppet-lifecycle lane agree on that list before anyone bumps the schema. This lane will not edit their files.
2. **Transform fields.** The provisional snapshot is player id, movement `0..7`, finite x/y/z, yaw, pitch, and tick. Confirm or replace that set before treating it as the replication pose. It is not a verified game pose.
3. **Framing.** v2 is a separate frame, not a payload inside v1 types 1..8. Nesting it under a new v1 type would keep the 16 MiB v1 cap and two length fields. Replacing the v1 frame would change `Network::Send`. Which one should the next transport change use?
4. **Panel.** PR #6 can later show display name, session id, and slot ids from `Hello` / `HelloAck`. Heartbeat `sendTimeMs` can feed a last-seen field that the panel does not have yet. No adapter was added, because that panel's files are on another branch.
5. **Sequence owners.** Control packets use `SessionMachine`'s counter. Snapshots use the caller's per-type counter. A future socket loop needs one agreed sender so those counters stay disjoint per type.

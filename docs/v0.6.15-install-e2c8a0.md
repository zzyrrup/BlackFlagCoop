## Discovered

### Confirmed — gate-setter install path

| Item | Value |
|------|-------|
| Direct E8/LEA/qword to `0x53F31A0` | **0** (same class as wrapper) |
| Tail-jmp stub | **`0x7BB020`** — `test [rcx+61],2`; if clear, **`jmp 0x53F31A0`**; alt path **`jmp 0xE95E80`** (worker B) |
| Arming caller | **`0x21085D0`** → `call 0x7BB020` |
| Arming preconditions | `[obj+0x98]==0`, `[obj+0x18]` / `+0xA8` present, **`test [obj+0x61],2` clear** |
| After arming | vcall `[vtable+0x2B0]` with `edx=2` |
| Table install | `.edata` **qword `0x9490078`** = `0x21085D0` (slot bundle with nearby `0x2108530` / `0x2108830`) |
| Bounds noise | `.vmp0` / `.vmp4` RVA32 hits (function bounds, not dispatch) |

**Verdict:** Gate-setter is reached through stub `0x7BB020`, itself called by arming helper `0x21085D0`, which is published in an `.edata` method/slot table. This is the offline install/dispatch path for establishing enrollment bit1.

### Confirmed — bit-writer install path

| Item | Value |
|------|-------|
| Direct E8/LEA to `0xF1C240` | **0** |
| Thunk `0xF1C230` | `mov rcx,rdx; mov dl,1; jmp 0xF1C240` (**pass bit=1**) |
| Thunk `0x210A9F0` | `mov rcx,rdx; xor edx,edx; jmp 0xF1C240` (**pass bit=0**) |
| Table install | `.edata` **`0x9303E30`=`0x210A9F0`**, **`0x9303E38`=`0xF1C230`** (adjacent slots) |
| Bounds noise | `.vmp4` RVA32 hit |

**Verdict:** Bit-writer is published as a pair of argument-adapter thunks in an `.edata` function-pointer table (set-1 / set-0 wrappers), not via E8.

### Confirmed — `0xE2C8A0` (859 B)

| Item | Value |
|------|-------|
| Role | Sorted **0x18-stride** packed-array ensure/insert helper (`count & 0x3FFF`) |
| Allocator | **yes** (`0x426EE50`) on miss/grow paths |
| Near-wrap | **calls `0x2EA0B00` twice** (`0xE2CA86`, `0xE2CB7B`) after copy helper `0x2EA0A20` |
| Key / `+0x61` / `+0x98` / enqueue helper | **no** |
| Callers E8 | **many** (≥40 capped) — widely reused |
| Relation | Feeds list helper `0x2EA0B00` (v0.6.14), **not** the gate-setter arming path |

**Hypothesis (not verified):** `0xE2C8A0` populates manager-side lists that UpdateActorLOD later drains; it is orthogonal to the `0x21085D0` gate-arming path.

### Cross

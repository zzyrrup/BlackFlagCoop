## Discovered

### Confirmed — TiHelper is a TypeInfo construct helper (not Lookup)

| Item | Value |
|------|-------|
| Entry | `0x43DCB00` (~28k E8 callers) |
| Args | `rcx`=TypeInfo*, `rdx`=existing object or null |
| `rdx != 0` | Early return `rdx` (passthrough) |
| `rdx == 0` | `flags=[ti+0xF6]&0x7F`, `size=[ti+0x20]` |
| Alloc | Runtime pool global `@0xAF6FD48` — freelist pop **or** vtable `call r9(pool, size, flags)` |
| Ctor | `icall [ti+0x50]` |
| **Not** | Lookup `0x429F9E0`, Allocator `0x426EE50` |

**Confirmed:** TiHelper constructs objects from a TypeInfo record via pool + `[ti+0x50]`. It is **not** a Lookup bridge into tight factories.

### Confirmed — Neigh keyHash / SpatTi do not feed tight factories via Lookup

| Check | Result |
|-------|--------|
| Lookup funcs also LEA NeighMeta/SpatTi/keyField | **0** |
| Tight factories LEA NS TypeInfo | **0** |
| Tight factories call TiHelper | **0** |
| LEA NS-TI → Lookup / tight | **0** |
| LEA NS-TI → TiHelper | Neigh VT20 / Spat VT20 / one other |

**Two distinct construct channels:**

1. **NS VT`[+0x20]` → TiHelper** — `lea` static TypeInfo (`0xAAD2290` / `0xACE83F8`) → pool construct.
2. **Tight factory Lookup → Alloc → `[ti+0x50]`** — generic; no offline RIP to Neigh/Spat TypeInfo.

### Confirmed — Size `0xB0` vs enrollment / `+0x98`

| Finding | Evidence |
|---------|----------|
| Neigh heap size | TypeInfo `+0x20` = `0xB0`; consumed by TiHelper |
| Hard-coded `Allocator(0xB0)` | **0** in 2000 sampled sites |
| NeighRel (ctor @ TI`+0x50`) | `xor eax,eax` then `mov [rcx+98],al` — **zero byte field** |
| NeighRel vs SideBlock | No call to SideBlock/Arming |
| Spat VT20 `+0x98` | `add rdi/rcx,98` inline spatial copy |
| SideBlock enroll | Still Alloc(`0x160`) → pointer store at `+0x98` (distinct layout) |

**Confirmed:** Size `0xB0` objects own a **byte** at `+0x98` zeroed at construct. That is **not** the enrollment SideBlock pointer-slot family (same offset, different layout — consistent with v0.6.27).

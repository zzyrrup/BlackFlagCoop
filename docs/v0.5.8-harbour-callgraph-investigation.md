## B1 — Relative call graph results

### Direct callers of export entry points

| Target | E8 callers | E9 callers | Abs VA pointer hits in image |
|--------|------------|------------|------------------------------|
| Find | **0** | **0** | **0** |
| DumpTo | **0** | **0** | **0** |
| LoadFrom | **0** | **0** | **0** |
| ClearUnsafe | **0** | **1** (`0x7B63581` → ClearUnsafe) | **0** |

**Interpretation:** Find / DumpTo / LoadFrom are **not** referenced by ordinary `call rel32` / `jmp rel32` or absolute VA immediates from scanned executable sections. They may be:

- export-only surfaces (tooling / Harbour runtime entry), or  
- reached only via register-indirect / computed calls not covered by this scan.

### ClearUnsafe internal chain (defensible)

From prologue bytes + E8/E9 decode:

1. `ClearUnsafe` (`0x69296F0`) **calls** `0x6929650` then **jmp**s to `0x6929450`.  
2. Inner `0x6929650` has **6** E8 call sites, including sites inside the Find/DumpTo/LoadFrom neighborhood (`0x692E430`, `0x692E796`, `0x692E87C`) — evidence of a **shared Harbour-cluster helper**, not of schema registration.  
3. External **E9** into ClearUnsafe from `0x7B63581` (`.impdata`).

### Shared “callee” `0x5014570`

Bounded scans of Find/DumpTo/LoadFrom each showed an early call to `0x5014570`.  
Prologue at that RVA: `48 3B 0D …` — pattern consistent with **`__security_check_cookie`** (or equivalent).  
Fan-in ≈ **115,949** E8 sites → **ubiquitous runtime helper**, not a Harbour registry primitive.

### Insert “callers”

102 E8 sites decode to stub RVA `0xD500`. Treat as **low-confidence / likely coincidental** (tiny stub RVA attracts false rel32 landings). Insert remains a no-op stub.

### Harbour cluster activity

Executable-section E8 destinations into `0x6928000–0x6930000`: **3060** sites.  
Shows dense code in the Harbour neighborhood, but **does not** attribute those calls to the named export entry points above.

### Function boundaries

Only **partially** defensible: ClearUnsafe’s short wrapper (call + jmp) is clear. Find/DumpTo/LoadFrom bodies are large; callee lists use a **bounded 0x800-byte window** and stop heuristics — not proven ends.

# v0.7.0 manual PC1 checklist

This checklist is for Cruz to run later. The v0.7.0 build did not launch the game, load a save, or copy an ASI into the game directory.

Installed ASI to preserve until you explicitly decide otherwise:

- Version: **v0.5.1**
- SHA256: `63B38877DDA7CC7CD9AB2619F94D3941C37F54C95A435EFE47084DC4CF2A50BE`

Candidate build (not installed):

- Version string in the log: `0.7.0-dev`
- Path: `build\bin\Release\BlackFlagCoop.asi`
- SHA256: see `reports/v0.7.0-validation.json` after the automated build

## Before you touch the game

1. Confirm the candidate SHA256 in the validation report is different from the v0.5.1 hash above.
2. If an ASI is already installed next to the game, hash it and confirm it is still v0.5.1. Keep that file. Do not delete it.
3. Copy the candidate aside only for this test, and plan to put v0.5.1 back afterward if anything looks wrong.
4. In the environment that launches the game, set `BFC_SESSION_PANEL=1`. Without that variable the panel is log-only and no sidebar is drawn.
5. Do not start a host or client for this first look. The plugin does not open a session socket on load.

## What you should see

1. The usual startup splash still appears.
2. A small click-through panel sits at the top-right. It does not take keyboard focus.
3. The panel text matches the idle roster:
   - `BlackFlagCoop session panel 0.7.0-dev`
   - Role Idle, State Idle, Session none
   - Connection: not started
   - Safety line: no second Edward is spawned; Player 2 is a session slot only
   - Slot 1 and Slot 2 are Unassigned, Not joined, Ready n/a, `Edward: not spawned`
4. The game still has one Edward. Nothing in this build creates a second character.
5. `%LOCALAPPDATA%\BlackFlagCoop\BlackFlagCoop.log` contains `SessionPanel:` lines for that same idle roster, plus `Session panel overlay started (BFC_SESSION_PANEL opt-in)` and `Session panel safety: no in-world second Edward`.

## What would be a failure

- The log version is still `0.5.1` (the candidate did not load).
- The panel claims a spawned Edward, a connected Player 2, or an open session when you did not start one.
- A second character appears.
- The game fails to reach the menu, or the panel steals input so you cannot play.

## After the look

1. Close the game.
2. Restore the v0.5.1 ASI if you swapped files, and check the hash again.
3. Note whether the sidebar matched the idle roster and whether gameplay input still worked.

Passing this checklist does not mean two-player co-op works. It only means the gated roster UI loaded.

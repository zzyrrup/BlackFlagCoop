## Why this slice

v0.6.5 and v0.6.6 recovered the deferred-queue consumer and the enqueue helper `0x2E97B60`. They did not recover an Edward, character, archetype, or possession factory. A second in-world Edward is not an evidence-backed change.

The code that is already real, and safe to extend without game memory, is the BFC session model: roles, session ids, player ids 1 and 2, and connection status. v0.7.0 turns that model into a roster the user can read.

The panel is a session placeholder. It is not a spawned character.

## What ships

- `SessionPanelInput` / `BuildSessionPanel` / `RenderSessionPanel` build a two-slot roster.
- Slot 1 is Player 1. Slot 2 is Player 2. Local and Remote follow the host/client ids used by the existing handshake (host = 1, client = 2).
- Presence is Not joined, Connected, Leaving, or Disconnected. Ready is n/a until that slot is Connected.
- Every snapshot hard-codes `inWorldEdward = false`. There is no setter.
- `InitializeASI` logs the idle roster and does not open a socket, scan memory, or draw the panel.
- `BFC_SESSION_PANEL=1` (also `on`, `overlay`, `true`) starts a click-through, non-activating text window. Any other value, including unset, stays log-only.
- The wire protocol is unchanged (messages 1–8).

## Acceptance criteria

Automated, required before this milestone is called built:

1. Idle roster: role Idle, session none, both slots unassigned and not joined, ready n/a.
2. Host waiting: Player 1 local and connected, Player 2 remote and not joined.
3. Active host: Player 2 connected, ready independent of the local ready flag.
4. Client view: Player 1 is remote, Player 2 is local.
5. Peer drop: Player 2 disconnected and ready returns to n/a; Player 1 stays connected.
6. Error: last error is rendered and Player 2 is not invented as joined.
7. No snapshot or render claims an in-world Edward.
8. Display-mode parser defaults to log-only.
9. Visual Studio 18 2026 x64 Release build of the ASI and `BlackFlagCoopSessionPanelTest` succeeds.
10. Candidate ASI SHA256 is recorded and is not the installed v0.5.1 hash.

Manual, not run by this milestone:

- User loads the candidate only after choosing to, with `BFC_SESSION_PANEL=1`, and checks the idle sidebar plus the log lines.
- User confirms the game still shows one Edward.

## Out of scope

- Launching Assassin's Creed, loading a save, or driving the game window.
- Copying the candidate ASI over the installed v0.5.1 file.
- PC2, save data, live memory, actor spawn, possession, or new protocol messages.
- Claiming LAN co-op, campaign sync, or two controlled Edwards.

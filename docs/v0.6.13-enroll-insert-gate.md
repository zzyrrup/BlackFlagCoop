## Discovered

### Confirmed — lookup key `0xB2898C8`

| Item | Value |
|------|-------|
| Section | **`.trace`** |
| Form | Opaque non-string blob (Anvil TypeInfo/key layout; dword/qword fields, not ASCII) |
| Classification | `opaque_anvil_typeinfo_key_in_.trace` |
| Enrollment use | LEA'd into `rdx` before `0x429F9E0` at sites `0x2E9B3D1` / `0x2E9B481` |
| **Also used by** | Deferred worker **`0x725400`** (same TypeInfo key on teardown path) |
| Other xrefs | Many LEA users across systems (Rideable, CoopAction helpers, etc.) — shared TypeInfo, not Edward-named |

**Verdict:** `0xB2898C8` is the **shared TypeInfo/key** for the LOD enrollment/activation object family. It does **not** expose a recoverable MSVC/`Actor` string name offline.

### Confirmed — `+0x61` gate write styles

| Style | Result |
|-------|--------|
| Imm `or …, 2` (bit1) | Essentially **absent** as a common pattern |
| Imm `or …, 4` (bit2) | **Confirmed** post-enqueue in wrapper (`0x2E98AA8`, `0x2E9B3D6`, `0x2E9B486`, …) |
| Register-form RMW / load-modify-store | Dominant path for other bit edits |

Enrollment gate remains: `([obj+0x61] & 6) == 2` (bit1 set, bit2 clear).

### Confirmed — insert / gate leads (key-user ∩ `+0x61`)

| RVA | Role signal | Notes |
|-----|-------------|-------|
| `0x725400` | **Worker teardown** (known) | Uses key; clears bit2 (`and al,0xFB`) / edits `+0x61`; nested chain |
| `0xF1C240` | **Parameterized `+0x61` bit writer** | `mov al,[obj+0x61]; and al,0xFE; or al,bl; mov [obj+0x61],al` + key LEA |
| `0x53F31A0` | **Gate setter (high signal)** | Nested `+0x18→+0xA8→+0x3CD0` + key lookup; **`or [obj+0x61], 0x0A`** (sets **bit1 + bit3**) |
| `0x4B5A560` | Membership / gate check | `test [+0x61],2` early-out if set; touches `+0x98`; SmallArray; key |
| `0x4D04450` | Membership / gate check | `test [+0x61],2` early-out; touches `+0x98`; SmallArray; key |
| `0x2EA0B00` | Near-wrapper list helper | Reads `+0x61`; SmallArray strings; key; nested |

**Hypothesis (not verified):** `0x53F31A0` (and/or callers of `0xF1C240` with bit1) establish enrollment eligibility; `0x4B5A560` / `0x4D04450` may insert into related lists when bit1 is clear. Exact SmallArray insert store sites still need deep-decode.

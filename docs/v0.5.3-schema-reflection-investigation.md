## 1. Recovered schema definitions

| Field | Value |
|-------|-------|
| File offset | `0xA1D77BE` |
| RVA | `0xA1D81BE` |
| VA | `0x14A1D81BE` |
| Section | `.edata` |
| Confidence | **high** |
| Evidence | **confirmed** |

Surrounding object:

```json
{"name":"PlayerPosition","compositions":[{"name":"player.position"}]}
```

Immediate neighbors are other **signal** compositions, for example:

- `StorePreloadAttemptStartSignal`
- `BoatNavigationStartSignal` / `BoatNavigationStopSignal`
- `SaveGameStartSignal` / `SaveGameStopSignal`
- `ProgressionPlayerInventorySignal` → `player.progression.inventory`
- many `context.start.*` / `custom.*` signals

**Classification:** analytics / telemetry / composition **signal catalog**, not a binary world-transform struct.

**Not found in this object:** `float`/`vector`/`quaternion` field types, stride, or serialization layout for coordinates.

- Classic MSVC `.?AV` RTTI remains sparse and non-Anvil-player (v0.5.2)

## 6. Final assessment

1. **Did we find a real player-position schema?**  
   **Partially yes, with an important caveat:** we confirmed a real **composition/signal schema entry** `PlayerPosition` → `player.position`. We did **not** find a real world-coordinate struct/layout.

2. **Did we find an Edward actor/entity type?**  
   **No.** Only content/UI string literals.

3. **Did we find a type registry connecting those structures?**  
   **No** verified registry. Composition + analytics schemas exist; linkage to runtime type IDs is unproven.

4. **Did we identify a credible actor creation pathway?**  
   **Not yet.** Only naming beacons (`CreateActorsDeferred*`, spawners).

5. **Evidence for multiple independent player-controlled characters?**  
   **None confirmed.**

6. **Next safest technical step toward observing Edward’s actual position?**  
   **v0.5.4 — Composition runtime binding research (still read-only first):**  
   - Catalog all `player.*` composition paths offline.  
   - Determine how composition/signal names are looked up at runtime (hash/StringId), using only non-invasive observation if/when tested.  
   - Prefer observing whether `player.position` payloads appear in telemetry/save/network channels before any memory scanning.  
   - Still refuse guessed offsets in the ASI until a reproducible read path is proven.

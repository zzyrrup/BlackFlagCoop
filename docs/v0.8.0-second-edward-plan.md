**Mode:** Offline PE (`SpawnCallers080`) plus a default-off plugin gate

The native character factory is **not confirmed**. This slice does not spawn an actor. It records the calls that are proven not to be that factory, and the plugin refuses to call them.

## Decision

| Question | Result |
|----------|--------|
| Candidate creation names | `SpawnCharacterParams`, `SpawnEntityParams`, `SpawnEntityBuilderParams` |
| What those functions are | Schema visitors. Each one `lea`s its type name and calls registrar `0x4572C60` |
| Direct callers | More schema visitors with the same registrar pattern. Zero factory candidates |
| Standalone `CreateEntity` / `SpawnCharacter` strings | Not present. Only the `*Params` names |

### Confirmed

- `0x80F2330` is the only function that loads the string `SpawnCharacterParams` (`0xA11DDC1`). It calls `0x4572C60` with hash `0xFB7FF6A5`, then calls the builder visitor `0x8E02960`. It does not call the generic allocator.
- `0x8E02960` loads `SpawnEntityBuilderParams` (`0xA11DDF0`), registers it (`hash 0x6A484E77`), then calls `0x8DFFB90`.
- `0x8DFFB90` loads `SpawnEntityParams` (`0xA11DC2D`) and registers it (`hash 0xB5BAEE39`).
- Every direct `E8` caller of those three functions is itself a schema visitor (`0x80F23E0`, `0x80F2580`, `0x80F27E0`, `0x80F2A20`, `0x821ABC0`, plus the parent visitors). Each loads a type name and calls `0x4572C60`.
- A second reported LEA one byte after each real `lea` is the opcode byte of the same instruction, not a second callsite.
- These are not the deferred queue (`0x1AC380`), the LOD enqueue path (`0x2E97B60` / `0x2E97FC0`), the `+0x98` side-block allocator (`0xE95E80`), or the generic allocator (`0x426EE50`).

### Same-table allocators (not a character factory)

Each visitor is stored as a qword in a run of code pointers. One slot in the entity and builder runs calls `Allocator` (`0x426EE50`) with a size in `edx`. That shows an object constructor on the same run. It does not show that the object is Edward, or that the call inserts anyone into the world.

| Run base | Visitor in that run | Allocator slot | Size in `edx` |
|----------|---------------------|----------------|---------------|
| `0x92D2030` | `0x8DFFB90` at index 8 | `0x34730` | `0x1528`, final vtable `0x92F9108` |
| `0x92D1F70` | `0x8E02960` at index 8 | `0x3DE6300` | `0x1530`, final vtable `0x92F9048` |
| `0x92D1EB0` | `0x8E02960` at index 8 | `0x32FF450` | not in the first instructions; the call is later |

`0x34730` and `0x3DE6300` use the game's thread-local allocator prologue (`cmp byte [pool+0x2A]`, `gs:[0x58]`) and then `mov edx, size; mov r8d, 8; call 0x426EE50`. The run base is the first code pointer walking backward from the visitor qword. It is not proven to be vtable slot 0.

The `SpawnCharacterParams` run at `0x92D19A8` holds `0x80F2330` at index 5. None of the scanned slots in that run call `0x426EE50`.

### Still uncertain

- Which method on these types actually builds a world actor.
- Whether the `0x1528` / `0x1530` allocations are the parameter objects, a character, or another type that shares the run.
- Owner VT constructors from v0.6.25 (`0x13612B0`, `0x5781490`) are still not this path.
- Possession and a second input context are untouched.

### Missing link

A callsite that fills a `SpawnEntityBuilderParams` object and then inserts a character into the world. The schema visitors do not do that. Calling `0x34730` or `0x3DE6300` would allocate an unidentified object and is not allowed in this build.

## What the plugin does

`SpawnContract` is compiled with `kInvokeNativeSpawn = false`. `AttemptSpawn()` returns immediately with target RVA 0. `InitializeASI` only logs that refusal. There is no function pointer, no memory write, and no env var that turns the call on.

The candidate version string is `0.8.0-dev`. The installed file is still v0.5.1 until a separate deploy approval.

## Vtable result

See `docs/v0.8.0-alloc-vtables.md`. The `0x1528` object keeps vtable `0x92F9108`. The `0x1530` object keeps vtable `0x92F9048`. Both pass through base `0x92F91C8`. `vt-8` is 0, so there is no MSVC RTTI name. Neither table is a confirmed character. `SpawnNPCParams` (`hash 0x94D05600` in `0x80F23E0`) is another schema visitor. `0x5E3DB0` copies fields through `0x5E3DF0`.

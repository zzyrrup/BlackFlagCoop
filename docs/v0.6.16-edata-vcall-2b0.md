## Discovered

### Confirmed — how `.edata` slots are consumed

No direct RIP `LEA`/`MOV` of the exact slot addresses. Consumers are **constructors that install nearby `.edata` table bases as object vtables / method tables**; runtime then indexes fixed slot offsets.

| Constructor | Installs base | Relation to slot |
|-------------|---------------|------------------|
| `0x2E97A50` | **`0x948FF50`** → `[obj+0]` | Arming slot `0x9490078` = base+**`0x128`** (vtable index 0x25) |
| `0x2E97F00` / `0x210AA00` | **`0x9490220`** → `[obj+0]` | Same arming table neighborhood |
| `0x59D9B90` | **`0x9303E28`** → `[obj+0x1D0]` | Bit slots at base+**`0x8`** / +**`0x10`** |
| `0x3225900` | **`0x9303DD8`** → `[obj+0]` | Bit-table neighborhood |

**Near-wrapper family note:** `0x2E97A50` / `0x2E97F00` sit beside enqueue helper `0x2E97B60` / wrapper `0x2E97FC0` — same subsystem installing these method tables.

**Verdict:** Slots are **vtable entries** in `.edata` method tables, not standalone function pointers with E8 callers.

### Confirmed — arming neighbor A `0x2108530`

| Item | Value |
|------|-------|
| Body | Tiny thunk: **`jmp 0x129E5190`** |
| `.edata` slot | `0x9490070` (adjacent to arming helper) |
| Target `0x129E5190` | If `[obj+0x98]≠0` → call membership **`0x4D04450`**; also `test [+0x61],2` → worker **`0x725400(dl=0)`**; packed-list walk |

**Verdict:** Neighbor A is the **teardown / membership** sibling of the arming helper (attach-side `0x21085D0` vs detach-side `0x2108530`).

### Confirmed — arming neighbor B `0x2108830`

| Item | Value |
|------|-------|
| Body | `mov rax,[rcx+18]; mov [rcx+50],rax; jmp 0x43E7750` |
| `.edata` slot | `0x9490060` |
| Target `0x43E7750` | `or [obj+0x23],1`; loads **`[vt+0x2B0]`** and **`[vt+0x2B8]`** and **compares to expected code pointers**; nested `+0x18→+0xA8`; flag bytes `+0x22/+0x25/+0x26` |

**Verdict:** Neighbor B validates that the object's vtable still has the expected `+0x2B0`/`+0x2B8` methods — identity/type gate around the same virtual slot the arming helper invokes.

### Confirmed — vcall `[vt+0x2B0]` with `edx=2`

Arming helper `0x21085D0` (after optional gate-stub call):

```
mov rax, [obj]           ; vtable
mov rax, [rax+0x2B0]     ; method
mov rcx, obj
mov edx, 2
jmp rax                  ; tail virtual call
```

Global byte scan found **80** `[reg±0x2B0]` sites (many unrelated field uses); **edx=2** co-occurrence is rare. The arming helper is the high-signal `edx=2` consumer on this path. Neighbor B **reads** the same slot for equality checks rather than calling it.
